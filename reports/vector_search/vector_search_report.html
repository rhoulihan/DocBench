Types: Float32 (baseline), Int8 (scalar quantization)

RAG1: Multi-Hop Graph Traversal

Purpose: RAG pattern - Find similar accounts and traverse relationships to find connected accounts.

Data: 10K accounts with embeddings + 200K transactions (20 per account)

Traversal: Same-tenant accounts via $graphLookup, shared-merchant accounts via transaction joins

ProtocolImplementation
MongoDB Native$vectorSearch → $graphLookup (same tenant) → $lookup (shared merchants)
Oracle JDBCCTE + self-join for same-tenant + shared merchant subqueries

RAG2: Temporal Transaction Aggregation (Weekly Stats)

Purpose: RAG pattern - Find similar accounts, join transactions (30 days), and aggregate by ISO week.

Data: 10K accounts with embeddings + 200K transactions (20 per account)

Aggregation: Group by ISO week → count, sum(amount), avg(amount) per week

ProtocolImplementation
MongoDB Native$vectorSearch → $lookup → $group by $isoWeek
Oracle JDBCCTE + GROUP BY TRUNC(date, 'IW') with window functions

RAG3: Customer 360 Profile Assembly

Purpose: RAG pattern - Find similar accounts and assemble complete customer profile with spending analysis.

Data: 10K accounts with embeddings + 200K transactions (20 per account)

Profile: txn_count, total_spent, avg_amount, days_since_last_activity, spending by category

ProtocolImplementation
MongoDB Native$vectorSearch → $lookup → $addFields with $reduce for category map
Oracle JDBCTwo CTEs: stats aggregation + category spending pivot

RAG4: Activity Pattern Detection (Rolling Window)

Purpose: RAG pattern - Find similar accounts and detect activity patterns using 7-day rolling windows.

Data: 10K accounts with embeddings + 200K transactions (90-day range)

Pattern Detection: Rolling 7-day count, burst detection (>2x avg), dormant detection (0 txns)

ProtocolImplementation
MongoDB Native$vectorSearch → $lookup → $setWindowFields for rolling window
Oracle JDBCCTE + SUM() OVER (RANGE BETWEEN 6 PRECEDING AND CURRENT ROW)

RAG5: Hybrid Context Ranking (Score Fusion)

Purpose: RAG pattern - Over-fetch candidates, compute hybrid score, and re-rank for final results.

Data: 10K accounts with embeddings + 200K transactions

Hybrid Score: 0.5×vector_score + 0.3×normalized_activity + 0.2×recency_score

ProtocolImplementation
MongoDB Native$vectorSearch (50 candidates) → $lookup → $setWindowFields for normalization → hybrid score → top-10
Oracle JDBCCTE with over-fetch + window functions for min/max normalization + hybrid formula
